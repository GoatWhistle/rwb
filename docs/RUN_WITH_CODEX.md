# Запуск Datum вместе с агентом через Codex

Нужны Docker с Compose (запущенный), Python 3.12+, Node.js 24 LTS и Codex CLI.
Команды ниже выполняются в bash: macOS, Linux или WSL2. Одного приложения Codex
без команды `codex` в терминале недостаточно для проверки авторизации скриптом.

## 1. Скачать и авторизовать Codex

```bash
git clone --branch feature/ai-agent https://github.com/GoatWhistle/rwb-new.git
cd rwb-new
codex login status
# Если вход ещё не выполнен:
codex login
```

Используется локальная авторизация Codex, отдельный OpenAI API key для чата
не нужен при входе через ChatGPT. Модель `gpt-6.1-sol` должна быть доступна
этому аккаунту. Проверка входа и повторное использование локальной авторизации
описаны в [OpenAI Docs](https://developers.openai.com/codex/auth).

## 2. Однократная подготовка

```bash
bash scripts/bootstrap-demo.sh
```

Скрипт создаст `.venv`, установит зависимости, создаст `.env`, поднимет PostgreSQL,
скачает исходные CSV, загрузит `raw`, соберёт `core`, выдаст права агенту и установит
фронтенд. Первое выполнение требует интернета и занимает несколько минут.
Это команда подготовки/пересборки данных; при обычном повторном запуске её не выполняйте.
Существующий `.env` сохраняется. Если `python3` старый:

```bash
PYTHON_BIN=python3.12 bash scripts/bootstrap-demo.sh
```

## 3. Запустить всё

```bash
bash scripts/run-demo.sh
```

Открыть **http://127.0.0.1:5173**. Скрипт запускает три процесса:

| Адрес | Сервис |
| --- | --- |
| `127.0.0.1:5173` | Русскоязычный фронтенд Datum |
| `127.0.0.1:8090` | API метрик и чат со стримингом |
| `127.0.0.1:8091` | Адаптер Responses к локальному Codex |

Терминал оставить открытым. `Ctrl+C` завершает запущенные сервисы, PostgreSQL
продолжает работать в Docker. Если база была остановлена, перед повторным
запуском выполните `docker compose up -d postgres`.

Проверить: `curl http://127.0.0.1:8090/api/health` и
`curl http://127.0.0.1:8091/health`. В чате спросить: «Покажи выручку по месяцам».

## Поиск по отзывам

SQL, метрики и чат работают через Codex. Для семантического поиска по отзывам
дополнительно нужен **POLZA_API_KEY**: Codex не заменяет сервис эмбеддингов.
Укажите ключ в `.env` и выполните:

```bash
.venv/bin/python -m backend.reviews index
```

Дождитесь `Review index ready.`. Первичная индексация отправляет тексты отзывов
на сервис эмбеддингов и занимает дополнительное время. После добавления ключа
перезапустите `run-demo.sh`. Без ключа/индекса агент честно сообщает о недоступности
семантического поиска; остальные инструменты работают.

## Настройки

Настройки по умолчанию уже в `.env.example`:

```dotenv
LLM_BASE_URL=http://127.0.0.1:8091/v1
LLM_API_KEY=local
LLM_MODEL=gpt-6.1-sol
```

`local` — заглушка для локального HTTP-адаптера, не настоящий API key.
Python SDK устанавливает закреплённый Codex runtime и использует сохранённый вход.
Если нужен именно установленный бинарник CLI, добавьте абсолютный путь
`GATEWAY_CODEX_BIN=/полный/путь/к/codex` в `.env`. Конфигурация runtime описана
в [OpenAI Docs](https://developers.openai.com/codex/sdk).

Диалоги и индекс сохраняются локально. `.env`, `.local`, `.venv`, CSV и
`node_modules` в Git не отправляются. Адаптер и API слушают только localhost.

.venv/bin/python -m uvicorn backend.codex_gateway:app --host 127.0.0.1 --port 8091
```

.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8090
```
